## Implemented workflow and current limitations

`main.py` dispatches through `run_workflow.py` to `poc.py`, `multi_agent.py`, or `rejudge.py`. Standalone settings use `batch_name=None`, one run-name string, and scalar identity counts. Batches use aligned run-name/count lists, explicitly including all five identities and zeros. Other settings are shared; single-agent/rejudge batches vary names only. New output roots are `outputs/single_agent/`, `outputs/multi_agent/`, and `outputs/rejudge/`. Batch metadata is in `queue_info/{queue.json,queue_status.json,events.jsonl}`. Standalone runs create no batch records.

The workflow validates every resolved run before paid calls, freezes active settings (including per-run budgets) and source hashes, reuses completed records, and stops on retained failures or uncertain interrupted calls without automatic retries. Clean between-call checkpoints can continue. Matching settings are required for resume; do not replace saved hashes to bypass conflicts. Direct runners and `run_multi_queue.py` retain legacy interfaces.

`csv_exports.py` rebuilds `trials.csv` and `diagnostics.csv` from saved JSON after attempts, including failures. Each has one row per trial, stable roster slots, and relative source paths. Scientific columns retain H_any, semantic verdict/recipient gate, per-agent identities and judge categories, actions, and communication. Diagnostics retain calls, usage, recorded/complete costs, errors and available provenance. Unknown judgments/usage stay blank; rejudge diagnostics count only new judge usage. Batch `analysis/` holds matching concatenations without pooled rows. Full prose remains in JSON. There is no general `analysis.py`, analysis toggle, routine text exporter, or new recipient-count analysis yet. Native multi-agent summaries and five-trial cost estimates remain.

Communication now selects one of `peer_awareness_null`, `peer_awareness_encouraged`, `peer_awareness_compulsory`, or `peer_awareness_compulsory_b4h`. `n_messages` accepts 3, 10, or 25 and requests a per-agent maximum across emails and forwards, counting an action once regardless of recipients. These are **prompt instructions**, not enforced routing gates or hard message limits. Runtime peer counts instead count directed recipients. Historical prompts without these settings must retain their original interpretation.
