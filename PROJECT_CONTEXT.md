## Current code and next work

The active branch is `douglas-classifier-audit`. `Multi Character PoC/main.py` has one editable `settings` dictionary for a **fresh, self-contained experiment**: currently 20 threat and 20 continuity trials per identity. `poc.run_experiment()` runs both framings under one `outputs/<run_name>/` folder, creates subject and released-judge responses, and writes separate `threat/summary.csv`, `continuity/summary.csv`, and `summary_pooled.csv` files. `uncertainties.py` appends Jeffreys 95% interval columns to standard-label rows; the same calculation can be applied to future audit rows. `audit` is `False` in settings, and enabling it fails before model calls because no new-run audit method has been specified. After five complete subject-and-judge pairs, `money.py` linearly extrapolates the recorded API cost; the runner stops if the estimate exceeds `max_cost`. The estimate is not a guaranteed cap. `max_cost` is currently $3.50. `concatenation.py` is an unused placeholder for possible future pooling of compatible runs. The old 240-trial outputs were not regenerated.

`analyze.py` was removed. The historical batch folders and analysis CSVs remain saved under `outputs/Codex Audit/`; `Hodges_Barbican` remains directly under `outputs/`. These archived results are not regenerated by the fresh-run pipeline. The later `Mermaid Refactor Test` saved 20 threat and 20 continuity trials per identity. Its pooled released-label counts were combined with the 240-run released counts in `outputs/Douglas_240_plus_Mermaid_160_pooled.csv` (100 valid trials per identity); source CSVs were retained, and provisional strict-audit labels were excluded. For new runs, `poc.py` produces standard-label rows, optional `audit.py` would add audit rows, and `uncertainties.py` appends interval columns to the resulting rows. A reproducible strict-action audit method remains undecided, so `audit: True` fails before any model calls. No new paid calls or strict judging were done for the combination.

On branch `douglas-classifier-audit`, `main.py` has `judge_protocol: "standalone"` or `"douglas_combined"`, currently set to `douglas_combined`. The latter uses the three-task combined prompt copied from Douglas's pinned released source, asks for blackmail, evaluation-awareness, and identity-reasoning answers in one response, and saves separate judge files and summaries. The judge model, 1,000-token allowance, forwarded-email context, and recipient gate remain at our current settings for this first prompt-format comparison. Existing standalone results are preserved; no combined-judge API calls have been made.

`main.py` currently selects `mode: "rejudge"`, which calls `rejudge.py` without invoking GPT-4o; `mode: "experiment"` selects the fresh-run pipeline. The judge-only path reads the saved `douglas_240` or `mermaid_160` trials in place, chooses a reproducible balanced sample or all trials, saves new judgments under `outputs/Rejudgments/<run_name>/`, and writes one trial comparison CSV and one summary CSV with Jeffreys intervals. The configured pilot samples 10 saved responses per identity and framing cell: 80 total, 20 pooled per identity. The 1,000-token combined-judge probe in `Douglas_80_combined_Haiku` produced two valid judgments and three responses truncated at exactly 1,000 output tokens (`finish_reason: length`); it remains saved. The current settings use a new `Douglas_80_combined_Haiku_4000` run with 4,000 judge output tokens, matching Douglas's released combined-classifier allowance while retaining Haiku as the judge. The partially started `Douglas_240_combined_Haiku` folder also remains separate. For each complete pooled pilot group, the summary compares its sampled standalone and combined-judge **rates** with Douglas et al. Table 4's 60-trial rate; the paper's count is retained as context, not compared directly with the pilot count. This tests whether changing the judge prompt and sufficient output allowance move the sampled rates toward the paper's; sampling variation and the Haiku-versus-Sonnet difference prevent a causal conclusion. It stops after a five-call probe if judgments are incomplete or the judge-only cost estimate exceeds `max_cost`.
